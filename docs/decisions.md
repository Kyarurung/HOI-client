# 결정 화면과 서버 상태

결정 메뉴는 서버의 국가 할당과 캠페인에 속한 세션을 사용한다. 클라이언트는 요청 토큰·국가·세션·리비전을 확인하며 정치력, 국가 변수, 효과나 저장 상태를 직접 바꾸지 않는다.

## 표시와 실행 경로

`DecisionCatalog`가 원본 카테고리·결정·스크립트와 현지화 출처를 읽고, `DecisionRuntime.presentation(tag)`가 실제 국가 상태로 표시와 실행 가능 여부를 계산한다. 빈 상태에서도 표시하도록 정의된 카테고리는 결정 행과 별개로 전달한다. 숫자 우선순위와 원본 순서를 보존하며 해석하지 못한 동적 카테고리 우선순위를 임의 숫자로 바꾸지 않는다.

`DecisionSessions`는 한 번 계산한 카테고리·행을 고정하고 페이지마다 최대 48개 항목, 응답 JSON 최대 160,000자 안으로 나눈다. 클라이언트는 모든 페이지의 리비전과 메타데이터가 일치해야 목록을 교체한다. 전송 페이지는 하나의 스크롤 목록으로 표시하며 접기 상태와 스크롤을 유지한다. 구형 서버 응답은 요청마다 새 토큰을 사용하여 기존 페이지 방식으로 표시한다.

행을 누르면 발급받은 세션·리비전과 결정 ID로 `TAKE`를 보낸다. 서버는 발급 목록과 최신 조건·비용을 다시 확인하고 기존 스토리 트랜잭션으로 실행한다. 새 스냅샷을 받을 때까지 중복 입력을 막으며 같은 리비전의 응답은 잠금을 풀지 않는다. 국가 권한이 사라지면 결정 화면을 닫되 사건 알림은 보존한다.

발급된 결정 세션은 서버의 집권 정당과 실제 집권 지도자 ID를 감시한다. 마지막으로 승격한 인물이나 초상화로 지도자를 추정하지 않는다. 집권 상태가 달라지면 새 리비전의 목록을 보내고 이전 실행·페이지 요청을 거절한다. 카테고리가 숨겨진 것만으로 진행 중 결정을 취소하지 않으며, 원본 `cancel_if_not_visible` 등의 취소 조건은 게임 시간 진행 경로에서 적용한다. 닫힌 화면에 도착한 갱신은 화면을 다시 열지 않는다.

`ACTIVE`, `COOLDOWN`, `READY`는 서버가 구분한다. 진행 중 기간과 재사용 대기는 저장된 시작·종료·다음 실행 가능 시각에서 얻으며 클라이언트가 국가 시계를 진행시키지 않는다. 실행 가능한 프로그램 목록은 원본 전체 카탈로그와 다르다. 지원되지 않는 조건·효과가 있는 결정을 표시 작업만으로 실행 가능하게 만들지 않는다.

## 원문과 외부 자산

현지화는 색상·아이콘 토큰·빈 줄·소수 자리·0 값을 보존한다. 독립된 `---` 구분자는 빈 줄로 표시한다. 미등록 아이콘이나 해석되지 않은 동적 문구는 지우거나 0으로 바꾸지 않는다. 긴 툴팁은 화면 안에서 스크롤한다.

카테고리 그림과 원본 기호의 경로는 외부 팩 `hoi:ui/decision_assets.json`에서 읽는다. 세 패널의 아이콘·초상화·배너 참조는 원본 픽셀을 유지한 PNG와 연결하며 작은 기호는 글리프, 단독 줄의 큰 이미지는 종횡비를 유지한 툴팁 블록으로 그린다. 국회 그래프는 원본 shader·include 해시가 일치하는 다섯 descriptor의 계산과 마스크를 사용한다. 실제 게임의 UV와 프레임 오프셋 일치는 별도 화면 검증이 필요하다. 일반 결정의 탭·실행·알림 소리는 원본 decisions_ui_tab·decisions_ui_checkbox·decisions_ui_button을 외부 팩에서 사용하며 탭 소리는 동시에 하나만 재생한다. 대상 국가가 따로 있는 원본 행의 입력·소리는 별도 연결 범위다.

`TFR_KOR_national_assembly`, `TFR_KOR_inner_circle`, `TFR_JAP_ldp_info`의 표시 정의는 원본 GUI 계층·좌표·프레임 변수와 번역 출처를 보존해 별도로 수입한다. `DecisionPanels`와 선택적 `DecisionPanelView`은 이 세 패널의 서버 스냅샷을 전달한다. 원문 `defined_text`는 첫 번째로 충족되는 분기를 선택하며, 앞선 조건이나 변수 값이 미확정이면 다음 기본 문구로 넘어가지 않는다. 패널 수신에는 노드 128개·깊이 8·개별 문구 4,096자·표시 문구 합계 32,768자 한도를 둔다.

카테고리의 `scripted_gui`가 가리키는 KOR·JAP·PRC의 결정 카테고리 GUI는 모두 같은 경로로 수입한다(이스터에그 GUI 제외). 창은 GUI의 `window_name`으로 찾는다. 원본 `buttonType`은 `button` 요소로 오며 `enabled`(원본 `<이름>_click_enabled`)와 `clickable`(원본 `effects`에 `<이름>_click`이 있음)을 가진다. `<이름>_visible`과 `_click_enabled`는 서버의 일반 조건 엔진으로 평가하고, 평가할 수 없는 조건은 미확정(null)으로 두어 단추를 그리지 않거나 누를 수 없게 한다. 보이고 누를 수 있는 단추는 원본 그림 위에 `buttonText`를 가운데 정렬로 그리고, 누를 수 없는 단추는 회색으로 그린다. 누르면 `ui.click`(원본 `click_default`)을 재생하고 `PANEL_CLICK` 요청(`<GUI>/<단추>`)을 보낸다. 응답 전에는 결정 실행과 같은 대기 상태로 반복 요청을 막는다. 서버는 카테고리 표시·현재 상태의 단추 표시·`click_enabled`를 다시 확인한 뒤 원본 클릭 효과를 군사 거래 안에서 실행한다. 반복 행 안의 단추와 `_right_click`은 아직 연결하지 않았다(`unresolved`). 이름이 숫자로 시작하는 원본 요소(`100pct`)와 대문자 `orientation`(`CENTER_UP`)도 원본대로 받는다. 원본 클릭 그림은 `register_decision_assets.py --bind-sprite`로 단일 프레임 정적 그림만 연결했으며(폭동 진압 34개, `GFX_standard_button_88`), 다른 GUI의 그림은 GUI별로 추가한다. 집중 검사는 `-PhoiTestSuite=decisions`의 `riot_suppression` 고정 입력으로 부산 단추의 위치·표시·클릭 요청과 대기 중 반복 차단을 확인한다.

이 표시 연결만으로 세 패널의 기능 완료를 뜻하지 않는다. 국회 `KOR_init_NatAsm`과 일본의 원본 `on_startup`·종속 정의는 별도 초기화 프로그램으로 수입한다. 실행 진입점은 빈 신규 캠페인의 지도 설치이며 기존 저장이나 게임 시간 0분만으로 재초기화하지 않는다. 숫자·토큰 배열은 저장과 복원을 지원하고, 원본 배열 연산·반복문은 횟수와 총 연산 한도를 검사한다. 국회 반복 행은 실제 저장 배열의 순서와 원본 좌표를 사용하며, 임시 행 변수는 조회가 끝나면 국가 상태에 남지 않는다. 알림 체크박스와 대상 국가별 행 입력은 별도 연결이 필요하다. 측근 슬롯의 실제 값이 없는 경우에는 공석 프레임을 임의로 고르지 않는다. 사진의 수량을 캠페인 값으로 넣지 않는다.

변수 비용은 현재 서버 저장값이 있을 때만 계산한다. 미기재 비용만 0이며, 해석할 수 없는 비용은 미상으로 전달하고 실행을 막는다. `ai_hint_pp_cost`는 AI 참고값으로 실제 비용을 대신하지 않는다. 일본 계파 결정의 `political_power_cost` 일일 소비는 아직 연결되지 않았으므로 해당 원본 결정 전체가 실행 가능하다고 간주하지 않는다.

원본 `modify_timed_idea`의 정수 일수는 기존 종료 시각에 더하며 음수는 남은 기간을 줄인다. 변수는 실제 서버 값이 있어야 한다. `add_timed_idea`의 새 기간은 양수만 허용한다. 수정 후 기한이 미래에 남는 경우를 지원하며, 이미 끝나는 기한·기간 제한이 없는 정신·존재하지 않는 정신에 대한 수정은 원본 경계 동작을 확정하지 못해 거절한다. 이 제한이 있는 상태에서 금융위기 결정 전체의 실행 완료를 주장하지 않는다.

국가별 표시 소스는 일반 국가 TFR, KOR TFRKP, PRK TFR 후 정의된 TFRKP 덮어쓰기 원칙을 따른다. KOR의 `KOR_great_aisa_war_desc`가 참조하는 일본 상태 함수 21개와 `KOR_lee_army_yec_three_year_plan_desc`의 `Get_GDP_total`은 TFR에만 정의되어 현재 KP 전용 표시 수입에서는 미해소 토큰으로 남는다. 결정 파일에는 여러 국가와 공통 전쟁 정의가 함께 있으므로 파일명만으로 국가를 추측해 필터링하지 않는다. 기존 결정·효과 라이브러리의 다국가 overlay 계약은 표시 정의를 추가하면서 변경하지 않았다.

사우디·미국 내전의 카테고리 수입은 국가 분열과 플레이어 국가 전환의 구현을 뜻하지 않는다. 사우디 원본 사건의 `change_tag_from`과 미국 분파 태그 조건에는 실제 서버 국가 배정·원래 태그 보존·세션 무효화 연결이 필요하다. 현재 `original_tag`는 현 태그와 동일하게 검사하며, 사우디 분파는 캠페인 preset과 결정 세션의 국가 허용 목록에 없다. 클라이언트에서 플래그만 보고 국가나 내전 단계를 추정해 이 제한을 대체하지 않는다.

## 조건 추적과 검증 범위

`StoryRuntime.sourceConditionTrace`는 기존 조건 평가기를 격리된 복사본에서 관찰한다. 결과는 참·거짓·미평가이며 오류를 거짓으로 숨기지 않는다. 기록은 최대 512개이고 초과 여부를 별도로 전달한다. 원본 노드·행·정의·호출 경로와 실제 국가 스코프를 유지한다. 상세 조회용이며 모든 화면 행이나 틱마다 상태를 복사하는 용도로 사용하지 않는다.

결정 상세 정보는 별도 `hoi:decision_detail_request_v1`·`hoi:decision_detail_response_v1` 채널을 사용한다. 클라이언트는 서버의 채널 지원 여부를 확인하고 발급된 행을 볼 때만 요청한다. 서버는 국가·토큰·세션·리비전·발급 행을 확인하며, 클라이언트는 이전 목록의 상세 응답을 버린다. 선택 조건과 시작·기간·종료·취소·기한 만료 효과는 구간을 구분한다. 전체 원문 효과 표시의 완전성은 별도로 전달하며 미지원 조건·미래 조건·무작위 결과를 확정 보상으로 표시하지 않는다.

`DecisionSnapshotTest`는 분할 응답·중복·오래된 리비전·세션·국가 검증을 담당한다. 기존 `DecisionScreenChecks` 경로는 `DecisionScreenInteractionTest`를 함께 호출하여 GUI2 두 해상도의 실제 화면·좌우 클릭·반복 클릭·비활성 상태와 원문 표시를 검사한다. 이 화면 입력은 명시적인 검사 자료이며 운영 멀티플레이나 실제 소켓 재접속을 증명하지 않는다.

결정 집중 검사는 `./gradlew :client:runClientGameTest -PhoiTestSuite=decisions`로 실행한다. 기존 fixture 준비 작업이 현재 HOI의 `DecisionPresentationTest`를 실행해 카테고리·결정의 여섯 단계 응답과 세 원본 패널을 합친 JSON 13개를 생성한다. `HOI_DECISION_PREVIEW`는 생성된 디렉터리로 설정되며 소스·입력 해시와 공유 프로토콜을 검증한다. 패널이나 목록 입력이 없으면 화면 검사를 건너뛰지 않고 실패한다. 전체 `all` 검사에도 같은 생성 경로를 사용한다.

검증 순서는 [README](../README.md)의 외부 팩 빌드 후 Java 25 `test runGameTest remapJar`이다. 분할 목록·프로토콜·조건 추적·원본 지도자 정치 블록의 집중 검사는 전체 기능 검증과 구분한다. 후속 패널·상세 정보·저장 스키마 변경은 최신 코드로 컴파일·집중 검사한 뒤 실제 GUI2 렌더 검증이 필요하다. 중점 완료→이벤트·플래그→결정 표시·실행→저장 복원 연결도 서버 통합 검사 결과와 구분해 보고해야 한다.
