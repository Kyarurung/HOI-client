# HOI-client

**Minecraft 26.3 · Fabric · Java 25용 HOI 전용 클라이언트 모드입니다.** 국가 메뉴·연구·생산·설계·지도와 음향을 표시하고, 게임 상태와 계산·저장은 HOI 서버가 관리합니다.

[설치와 조작](#설치와-조작) · [빌드와 검증](#빌드와-검증) · [화면 기준](docs/ui.md) · [구조](docs/refactoring.md) · [음악](docs/audio.md)

## 저장소 구분

| 저장소 | 역할 |
| --- | --- |
| **HOI-client — 현재 저장소** | 클라이언트 화면·입력·지도 렌더링·음향 |

## 설치와 조작

1. Minecraft **26.3**, Fabric Loader **0.19.5 이상**, Fabric API **0.161.0+26.3**를 설치합니다. 버전 기준은 [gradle.properties](gradle.properties)입니다.
2. Minecraft를 완전히 종료한 뒤 `hoi-client-1.0.0+26.3.jar`를 플레이어의 `mods/`에 넣습니다. 공유 `hoi_protocol`은 JAR에 포함되어 별도로 설치하지 않습니다.
3. HOI 서버에 접속하고 서버가 제공하는 리소스팩을 모두 수락합니다. UI·지도·모델·음향은 외부 팩에서 읽습니다.
4. OP가 `/선택`으로 국가 선택 단계를 열면 각 플레이어가 국가를 선택하고 `/준비`로 준비하며 한 번 더 입력하면 준비를 해제합니다. 관리자가 `/시작`으로 캠페인을 시작합니다.

| 조작 | 기능 |
| --- | --- |
| `F` | 캠페인 HUD의 마우스 커서 열기·닫기 |
| `/hoi menu` | 국가 메뉴 열기 |
| 메뉴 연구 아이콘 | 연구 화면 열기 |
| 연구 트리 휠·가로 휠·우클릭 드래그 | 트리 이동 |
| 생산 공장 ±에서 `Shift` | 공장 10개 단위 요청 |

HUD가 없는 상태에서는 F의 기본 보조 손 교체를 유지합니다. R 연구 단축키와 클라이언트 `/hoi` 루트는 등록하지 않습니다. 캠페인 시작·정지·배속과 저장 규칙은 [HOI 조작 안내](https://github.com/Kyarurung/HOI#operations)를 따릅니다.

**실행 중인 클라이언트의 JAR을 교체하지 않습니다.** `ZipFile invalid LOC header` 또는 `client-sided command 'hoi start'` 오류가 있으면 호환되는 JAR을 설치하고 클라이언트를 완전히 다시 실행합니다. 서버와 클라이언트의 통신 형식도 맞아야 합니다.

`Failed to decode packet 'clientbound/minecraft:remove_entities'`로 연결이 끊기면 해당 접속 시각의 클라이언트 로그와 disconnect 보고서를 서버 로그와 함께 확인합니다. 이번 26.3 전환에서 확인한 가변 엔티티 ID 목록 문제는 HOI 서버의 패킷 생성 시 복사로 수정합니다. 리소스팩이나 클라이언트의 오류 무시 처리로 해결하지 않습니다. 자세한 원인과 모의 연결 검증은 [서버 지도 문서](https://github.com/Kyarurung/HOI/blob/main/docs/warfare/terrain.md)에 있습니다. 개발 빌드의 통과와 운영 서버에 설치된 JAR은 구분해야 합니다.

## 화면 범위

국가 정보·결정·정보기관·연구·무역과 경제·건설·생산·모병과 배치·군수·장교단을 서버의 비공개 응답으로 표시합니다. 기갑·해군·공군 설계는 서버가 발급한 부품과 연구 조건을 사용합니다. 원본 이미지와 설명이 존재하는 것만으로 해당 원작 기능 전체가 구현된 것은 아닙니다.

모든 셀의 크기·여백·정렬과 주 시각 검증은 **GUI scale 2**가 기준입니다. 플레이어의 GUI 배율 설정을 강제로 바꾸지 않습니다. 한국어와 툴팁은 TFR 한글패치의 원문 키·색상·빈줄을 따르며 `---`는 빈줄로 표시합니다. 세부 표시 규칙과 미지원 범위는 [화면 기준](docs/ui.md), 게임 계산 범위는 [HOI 문서](https://github.com/Kyarurung/HOI/blob/main/docs/README.md)를 참고하세요.

## 빌드와 검증

먼저 인접한 HOI-resourcepack에서 의존성을 설치하고 팩을 빌드합니다.

```powershell
python -m pip install numpy==2.3.5 Pillow==12.3.0
python scripts/build_pack.py
```

이후 **HOI-client 루트**에서 Java 25로 실행합니다.

```powershell
.\gradlew.bat test runGameTest remapJar --console=plain --no-daemon
```

| 목적 | 명령·위치 |
| --- | --- |
| 설계 화면 집중 검증 | `.\gradlew.bat test runGameTest remapJar -PhoiTestSuite=designers --console=plain --no-daemon` |
| 음악 집중 검증 | `.\gradlew.bat test runGameTest remapJar -PhoiTestSuite=audio --console=plain --no-daemon` |
| 개발 클라이언트 | `.\gradlew.bat :client:runClient` |
| 배포 JAR | `build/libs/hoi-client-1.0.0+26.3.jar` |
| JUnit 보고서 | 각 모듈의 `build/reports/tests/test/` |
| 렌더링 캡처 | `client/build/run/clientGameTest/screenshots/` |

다른 팩 경로는 `-PhoiResourcePack=<resources.zip 절대 경로>`로 지정합니다. 같은 폴더의 manifest와 모든 분할 ZIP이 필요합니다. Linux에서는 `./gradlew`, 화면이 없는 환경에서는 `xvfb-run -a ./gradlew test runGameTest remapJar`를 사용합니다.

렌더링 GameTest는 실제 Minecraft 렌더러와 서버 응답 fixture를 사용합니다. 운영 서버의 실제 접속·다중 사용자 동기화·HTTP 팩 다운로드·추가 렌더링 모드 조합은 별도 확인 대상입니다. 빌드와 검증은 운영 서버를 실행하거나 배포하지 않습니다.

CI는 비공개 팩의 읽기 전용 키 `HOI_RESOURCEPACK_SSH_KEY`와 워크플로에 고정한 팩 커밋을 사용합니다. 자격 증명이 없는 외부 PR에서는 전체 렌더링 검증을 실행할 수 없습니다.

서버 응답의 권한·세션·리비전을 유지하고 늦은 응답이 닫힌 화면을 다시 열지 않도록 합니다. 공유 프로토콜 변경은 HOI의 복사본과 함께 적용하며 페이로드 타입을 수신기보다 먼저 등록합니다. 정적 자산과 서버 계산을 클라이언트 JAR에 복제하지 않습니다.


공군 생산 목록만 자원 칸 왼쪽에 역할 아이콘을 표시합니다. 공군 조정치 툴팁은 서버의 임무별 합산 효과와 평균 여부를 사용하며, 원본 임무 이름·색상·`(평균)` 표기를 유지합니다. 열린 슬롯 툴팁은 서버가 발급한 실제 국민정신 아이콘과 효과를 표시합니다. 테스트의 `air-mission-effects-fixture.json`과 `tokyo-slots-fixture.json`은 HOI 서버 GameTest에서 생성합니다.

전용 클라이언트의 atlas 차원에서는 동기화된 보더 중심을 기준으로 실제 지도 가로·세로를 복원하여 직사각형 보더 표시와 충돌을 적용합니다. 일반 차원에는 적용하지 않습니다. 운영 서버 접속과 다중 플레이어의 실제 화면 확인은 개발용 테스트와 별도입니다.

F로 연 지도 커서 화면에서 좌클릭을 누른 채 드래그하면 화면의 부대 HUD를 영역 선택합니다. 드래그 영역은 흰색 테두리만 그리고 내부는 투명하게 유지합니다. 기본 지도는 사단, 해군 지도는 함대, 공군 지도는 비행단만 선택하며 다른 지도에서는 병력을 선택하지 않습니다. 드래그하지 않은 클릭은 기존 HUD 선택·지도 상세 열기를 유지합니다. 선택 외곽선은 서버 스냅샷 갱신 동안 유지되고, 표식 삭제·차원 변경·만료·연결 해제 시 해제됩니다. 선택은 클라이언트 표시 상태이며 이동 명령을 실행하지 않습니다. GUI2 렌더링 검사에서 드래그 사각형·다중 외곽선·역방향 드래그를 검증하고 지도별 병종 필터를 검사합니다. 실제 운영 서버 접속 검증은 별도입니다.

육군 정보 부족 표식은 수량을 ?로 표시하며 조직력·내구도는 서버 값 그대로 표시합니다. 편제는 서버가 보낸 최소–최대 범위를 표시하고 보급은 ?로 표시합니다. unit_hud_v4를 사용하므로 서버·클라이언트를 함께 갱신해야 합니다. 모병 UI의 충원 장비 이름이 응답 목록에서 누락되면 식별자로 대체하며, 누락 참조가 포함된 화면도 GameTest에서 검사합니다.

사단 툴팁은 TFR 기본 스타일을 유지합니다. 관계별 색상은 부대 HUD와 사단 툴팁의 병종 아이콘에 적용합니다(자국 초록, 적군 빨강, 동맹 파랑, 제3국 회색). 툴팁의 기본 배경·문구·텍스트 색상은 유지합니다. GUI2 관계별 고정 스냅샷을 렌더링하며 운영 캠페인의 실제 접속 확인은 별도입니다. 해군·공군 HUD에는 별도 툴팁을 표시하지 않습니다. 외교 화면의 국민정신 영역은 GUI2 기준으로 1GUI 아래로 옮겼으며 아이콘과 클릭·호버 영역도 함께 이동합니다.

`/hoi-research`는 제거했습니다. `/준비`는 일반 플레이어, `/시작`은 OP 전용 서버 명령입니다. 클라이언트는 이 명령들을 등록하거나 자동완성 권한을 우회하지 않습니다.

생산 라인의 비축 수량은 충원·개선 상태에서 원본 노란색(`#FFBD00`), 비축 상태에서 초록색(`#009F03`)으로 표시합니다. 상태 아이콘과 같은 수요 판정을 사용하고 충원·개선·비축 아이콘과 수량을 기존 위치에서 각각 1GUI 아래로 이동하고 우측 정렬은 유지합니다. GUI2 렌더링 검사는 열린 화면에서 충원 → 개선 → 비축 → 충원 응답을 적용해 실제 수량 글자의 색상을 확인합니다. 전체 `test runGameTest remapJar --console=plain --no-daemon` 통과 후 1GUI 위치 보정은 같은 명령의 `-PhoiTestSuite=designers`로 재검증했습니다. JUnit 100개와 생산·설계 렌더링 검사가 통과했으며, 보정 전후 이미지에서 수량의 가로 위치 유지와 아래로 2픽셀 이동을 확인했습니다. 최종 클라이언트 JAR도 검사했습니다. 운영 서버와 연결한 멀티플레이 검증은 별도입니다.

건설 상단의 사용 공장·건설 속도·에너지와 소비재 행도 원본 문구·색상·빈 줄을 유지하며 서버 계산값을 표시합니다. 에너지 상단은 클릭하면 무역 화면을 엽니다. GUI2 렌더링에는 네 툴팁의 별도 스크린샷이 포함됩니다.

건설 아이콘·건설 라인 툴팁은 서버의 원본 형식 텍스트를 표시하며 숫자를 다시 반올림하거나 연속 빈 줄을 합치지 않습니다. 연구 잠금은 `construction/*_disabled`와 원본 `£trigger_no` X 아이콘으로 구분합니다. `ScreenConstructionTest`는 GUI2 잠금·해제 화면, 비활성 클릭 차단, 별도 라인 툴팁 및 작은 창 호환성을 실제 렌더러로 검사합니다. 테스트 스냅샷 검증이며 운영 멀티플레이 동기화 검증은 아닙니다.

건설 UI는 원본 행·진행 막대·숫자 칸·우선순위 버튼을 사용하며, 국가 계획과 무역 상품은 사용 중일 때 소비재 아래 별도 행으로 표시합니다. 주 건물·공유 건물·지역 건물에는 원본 아이콘과 설명 툴팁이 있습니다. 언어 키 `hoi.construction.group.*`는 설치 원본 `STATE_BUILDINGS`, `SHARED_BUILDINGS`, `PROVINCE_BUILDINGS` 및 `_DESC`에서 가져오며 한국어 패치를 우선합니다. 오른쪽 건물 선택 버튼은 원본 이미지의 검은 사각 배경을 그대로 유지하며 클라이언트가 덧그리던 바깥 배경·테두리만 생략합니다. 버튼 간격은 가로·세로 1GUI이며 선택된 버튼은 흰색 테두리로 표시합니다. 클릭·툴팁·연구 비활성 동작은 유지합니다. 건설 라인 건물 아이콘은 별도 `taskTooltip`으로 수량·다음/전체 완료 일수·건물 설명과 현재 효과를 표시합니다. 위치·작업·민간공장 수·우선순위 열 제목은 원본 `CONSTRUCTION_LOCATION_*`, `CONSTRUCTION_TASK_*`, `CONSTRUCTION_FACTORIES_*`, `CONSTRUCTION_PRIORITY_*` 설명을 표시합니다. 우선순위 위·아래 버튼은 공통 툴팁에서 클릭과 Shift 클릭 안내를 표시합니다. 건설 행의 우선순위 위·아래 화살표와 취소 X 버튼은 함께 1GUI 위로 보정하며 클릭·호버 영역도 같이 이동합니다. 민간공장 진행 행, 원자로·발전소·에너지 농장 대기 행, 네 열 제목 및 우선순위 버튼을 GUI2로 캡처하며, GUI2 테스트 화면의 수치는 테스트 스냅샷입니다.

조선소 5칸·10칸 행도 군수공장과 같은 격자 좌표를 사용하며, 폭이 더 넓은 원본 조선소 아이콘의 비율 축소로 생기는 수직 중앙 여백만 보정해 군수공장 아이콘의 윗선을 맞춥니다.

반환 기능 제거 이전의 전체 검증: test runGameTest remapJar 통과, JUnit 101개 및 GUI2 실제 렌더링 검사 통과. 국가 해방/영토 반환과 게이지 유무 네 조합, 반환 확인·취소, 조선소 5칸·10칸 아이콘 정렬과 함정 건조 일수, 긴 배치 대상 이름 말줄임표를 확인했습니다. 서버 공유 소스 34개와 최종 중첩 프로토콜 JAR 해시가 일치합니다. 운영 서버 배포·재시작과 운영 멀티플레이 검증은 수행하지 않았습니다.

해방·반환 금지 최종 검증: test runGameTest remapJar 전체 통과, JUnit 101개 통과. GUI2에서 민간 감독·주둔군 편제 상세와 두 금지 툴팁을 촬영하고, 활성 값이 들어온 응답에서도 비활성 유지 및 강제 버튼 호출 시 요청·확인창 부재를 검사했습니다. 최종 JAR의 반환 실행 요청·확인창 제거와 서버 통신 모듈 일치를 확인했습니다. 운영 배포·재시작·운영 멀티플레이 검증은 수행하지 않았습니다.

## 전략 지도 원거리 표시

HOI 전략 지도에서는 서버 청크 시야 밖의 바닥도 사용자가 설정한 Minecraft 렌더 거리까지 표시합니다. `hoi:atlas_terrain_v1`을 지원하는 서버·클라이언트 JAR가 모두 필요하며, 일반 월드나 사용자 설정값은 바꾸지 않습니다. 현재 플레이어에게 허용된 지도 색상·높이를 서버에서 받아 그리므로 방문한 청크를 저장하는 Bobby 방식과 다릅니다. Bobby 소스나 디스크 청크 캐시는 포함하지 않습니다.

로드된 가까운 청크는 기존 렌더러를 사용합니다. 먼 바닥은 단순화한 지형이며 해저·수면 파동·블록 엔티티는 포함하지 않습니다. 경계·도시·시설·부대의 기존 64블록 표시 거리는 유지됩니다. 지도·지배권·비공개 색상 변경은 새 리비전으로 반영하고 지도 전환·연결 종료 시 원거리 데이터를 해제합니다. 리소스팩 재로딩 시 기존 메시의 텍스처 참조를 다시 구합니다.

`gradlew.bat test runGameTest remapJar -PhoiTestSuite=distant-terrain --console=plain --no-daemon`은 통신·페이지 조립 검사와 실제 클라이언트 렌더링 픽스처를 실행합니다. 픽스처는 서버 거리 제한 밖 352블록 이상의 지형 표시, 빨강→파랑 갱신, 일반 월드의 거리 제한 복원을 확인합니다. 운영 서버 접속 및 Sodium 병용 검증·FPS/MSPT 개선 측정은 별도이며 수행하지 않았습니다.

원거리 지도 추가 후 기본 전체 검증 명령도 통과했습니다. 클라이언트 JUnit 64개와 공유 프로토콜 43개, 기존 전체 클라이언트 GameTest 화면 검증을 실행했고 최종 클라이언트 JAR의 렌더러·mixin·중첩 프로토콜 포함 및 테스트 전용 차원 제외를 확인했습니다. 운영 설치와 멀티플레이 검증은 수행하지 않았습니다.

## 일반 지형의 Bobby 원거리 표시

일반 Minecraft 지형과 다른 서버용으로 별도 Bobby `5.2.15+mc26.3-hoi.1` 호환 수정본을 제공합니다. 공식 배포본은 26.2까지이므로 26.3의 청크·조명 패킷 및 렌더링 API에 맞춰 수정했습니다. 설치된 Sodium 0.9.2 환경을 지원하며 해당 버전을 필수 의존성으로 명시했습니다. 기본 렌더러는 캐시 검사는 통과했지만 실제 원거리 지형이 보이지 않아 지원 대상으로 포함하지 않습니다.

서버에서 받은 청크만 `.bobby`에 저장합니다. 미방문 지형이나 먼 엔티티를 생성하지 않으며 다시 수신하기 전에는 변경 전 지형이 남을 수 있습니다. 서버·시드·차원별 캐시를 분리하고 HOI 전략 지도는 캐시 대상에서 제외해 전용 원거리 표시를 유지합니다. 사용자의 렌더 거리·GUI 배율은 변경하지 않습니다. 싱글플레이 캐시는 Bobby의 별도 설정으로 켤 수 있습니다.

[소스·라이선스·재현 절차](third_party/bobby/README.md)에 원본 커밋, 수정 패치와 검증 범위를 기록했습니다. 실제 클라이언트 GameTest에서 저장·재로딩·실시간 청크 교체·차원 분리·지도 제외를 검증하고 Sodium 원거리 표시를 화면으로 확인했습니다. 임의의 외부 서버 접속 및 Iris 셰이더 조합은 별도 검증입니다.

사용자 요청으로 Fabulously Optimized(2)의 Minecraft 26.3 인스턴스에 새 HOI 클라이언트와 Bobby 수정본을 설치하고 Prism으로 실행했습니다. 이전 HOI JAR은 인스턴스의 .minecraft/hoi-backups/bobby-20260929-120730/에 보존했습니다. 실제 모드 구성으로 초기화 완료와 실행 프로세스 유지를 확인했으며, 서버 접속·셰이더 지형 화면 검증은 수행하지 않았습니다.

배포 버전은 `1.0.0+26.3`이며 내장 `hoi-protocol-1.0.0+26.3.jar`도 같은 버전을 사용합니다. 모드 표시 아이콘은 기존 HOI-client의 TFR 로고 PNG를 그대로 복사합니다(SHA-256 `3da4c74a23c33a7aba8b7e1d507b2c4ed8a85cbcd3eeb6e30b015acaa44cd0c2`). 이 표시용 로고만 JAR에 포함하며 게임 UI·지도 자산은 외부 리소스팩에 유지합니다.

`1.0.0+26.3` 패키징 검증: Java 25의 `test runGameTest remapJar --console=plain --no-daemon`으로 JUnit 107개와 실제 클라이언트 전체 렌더링 GameTest를 통과했습니다. 원거리 지도 회귀 검사는 일반 월드로 돌아온 뒤 서버 시야 거리 2를 검사 직전에 설정하여 내장 서버의 자동 거리 갱신과 경합하지 않도록 했습니다. 최종 JAR의 버전·내장 프로토콜·TFR 아이콘 포함 여부를 확인했으며, Mod Menu 목록에서의 아이콘 육안 확인과 운영 멀티플레이 검증은 별도입니다. 이번 산출물은 설치된 클라이언트 JAR에 덮어쓰지 않았습니다.
