# HOI-client

Minecraft **26.2 · Fabric · Java 25**용 HOI 전용 클라이언트입니다. 자국 현황, 연구, 정보기관과 지휘관 상세를 표시하며 연구·첩보 조작은 인증된 서버 API로 요청합니다.

| 저장소 | 역할 |
|---|---|
| [HOI-client](https://github.com/Kyarurung/HOI-client) | 이 저장소. 클라이언트 모드 소스·빌드·UI 테스트 |
| [HOI-server](https://github.com/Kyarurung/HOI-server) | 서버 실행 파일·모드·설정이 들어가는 운영 폴더 |
| [HOI](https://github.com/Kyarurung/HOI) | 서버 모드 소스·전략 시뮬레이션·게임 콘텐츠·위키 참고 문서 |
| [HOI-resourcepack](https://github.com/Kyarurung/HOI-resourcepack) | 비공개 원본·PNG 자료와 실행용 UI·지도·모델 리소스팩 |

## 설치

1. 플레이어의 Minecraft 26.2에 Fabric Loader 0.19.5 이상과 Fabric API 0.159.0+26.2를 설치합니다.
2. `hoi-client-0.1.0-SNAPSHOT.jar`를 플레이어의 `mods/` 폴더에 넣습니다.
3. HOI 서버에 접속하여 `/hoi start`로 국가를 선택합니다.
4. `/hoi ready`로 전원 준비를 마치면 게임이 일시정지 상태로 시작합니다. **R**, **`/hoi research`** 또는 `/hoi-research`로 연구 화면을 엽니다. 키는 조작 설정에서 변경할 수 있습니다.

`/hoi menu`로 국가 메뉴를 엽니다. 서버가 제공하는 Polymer 리소스팩을 수락해야 UI 이미지·지도·사단 모델이 표시됩니다. 이미지와 모델은 HOI-resourcepack에서 제공하며 클라이언트 JAR에는 포함하지 않습니다. 공유 `hoi_protocol`은 JAR에 내장되고, 전략 계산·저장은 서버가 담당합니다.

## 빌드와 테스트

먼저 인접한 `HOI-resourcepack` 저장소에서 `python scripts/build_pack.py`를 실행합니다. 이미 변환한 PNG가 포함되어 있어 재빌드에는 Steam이나 Pillow가 필요하지 않습니다. 다른 위치의 팩은 Gradle에 `-PhoiResourcePack=<resources.zip의 절대 경로>`로 지정합니다. 이후 Java 25로 실행합니다.

```bash
./gradlew test runGameTest remapJar --console=plain --no-daemon
```

Windows PowerShell:

```powershell
.\gradlew.bat test runGameTest remapJar --console=plain --no-daemon
```

출력물은 **`build/libs/hoi-client-0.1.0-SNAPSHOT.jar` 하나**입니다. `test`는 프로토콜·레이아웃 JUnit, `runGameTest`는 실제 Minecraft에서 외부 팩 로딩, 10개 메뉴, 패널 비율, 6개 기준 연구 슬롯, 첩보 선택·응답 대기·권한 만료, 키보드 비행과 창 크기 변경을 검사합니다. 개발 실행은 `./gradlew :client:runClient`입니다. Linux에서는 `xvfb-run -a ./gradlew test runGameTest remapJar`를 사용합니다. CI는 `HOI-resourcepack`에 등록한 읽기 전용 배포 키의 개인 키를 `HOI_RESOURCEPACK_SSH_KEY` Actions 저장소 시크릿으로 사용합니다. 해당 키는 이 비공개 리소스팩 저장소에만 접근하며, 체크아웃 후 자격 증명을 유지하지 않습니다. 팩 버전은 워크플로의 커밋 SHA로 고정합니다. 팩을 갱신할 때 해당 SHA도 함께 갱신하고 렌더링을 검증합니다. 이 시크릿을 사용할 수 없는 외부 PR에서는 전체 렌더링 검증을 실행할 수 없습니다.

테스트 이미지는 `client/build/run/clientGameTest/screenshots/`에 생성됩니다. UI 테스트는 시험용 데이터로 렌더링을 확인하며, 실제 다중 접속 서버에서 연구 완료까지의 전체 연동 검사는 별도입니다.

## 화면과 게임 규칙

메뉴는 HOI식 금속 프레임, 어두운 내용 영역, 입체 제목 띠와 회색 선택 표시를 사용합니다. 상단은 원작 버튼 이미지의 테두리를 그대로 살린 왼쪽 도구 모음이며, 화면 전체에 넓은 버튼을 늘어놓지 않습니다. 국가 정보의 하위 탭과 경제·무역 전환도 아이콘만 표시하고 툴팁·접근성 이름을 유지합니다. 새로고침 버튼과 서버 현황 표시는 없으며 서버 현황 자동 조회는 유지합니다. 하단에 기관 관리처럼 실제 동작이 없는 메뉴는 내용 영역을 끝까지 사용합니다. 이미지 팩은 기존 HOI-resourcepack을 사용하며 추가 이미지를 JAR에 넣지 않습니다. GameTest는 일반·소형 창의 메뉴, 상세 창, 하위 탭 및 버튼 겹침을 실제 렌더러에서 검사합니다. 테스트에 보이는 국가 수치는 화면 검증용 데이터이며 운영 서버의 현황이나 다중 접속 동기화 검증을 뜻하지 않습니다.

상단 메뉴 순서는 국가 정보, 결정, 정보기관, 연구, 무역 & 경제, 건설, 생산, 모병 및 배치, 군수, 장교단입니다. 공용 메뉴는 연구 슬롯·트리·기술 상세에서도 유지합니다. 국가 정보 버튼은 왼쪽에서 두 줄 높이를 차지하고 오른쪽은 높이 약 40%의 지표 줄과 약 60%의 메뉴 아이콘 줄로 구성합니다. 스크린샷처럼 작은 자원 표시 줄 아래에 메뉴 아이콘을 배치하며, 국가명·국가 코드·시간·배속과 업적은 상단에 넣지 않습니다. 지표는 정치력·안정도·전쟁 지지도·인력·공장·연료·병참 상황·수송·지휘력·육군 경험치·공군 경험치·해군 경험치·집권 정당 지지도 순서입니다. 핵폭탄·실질 GDP·국가부채도 표시합니다. 세계 긴장도는 국가 정보 버튼과 같은 크기로 오른쪽 끝에 고정하고 TFR 원본 DEFCON 이미지 아래에 %를 표시합니다. `world_tension_icon_big_strip.dds`의 10개 프레임을 10% 단위로 전환하며 0~9%는 첫 프레임, 90~100%는 마지막 프레임입니다. 숫자와 DEFCON 글자, 색상, 투명도를 그대로 보존하며 같은 숫자가 두 구간에 반복되는 원본 배열을 유지합니다. 서버 값이 없으면 특정 DEFCON 단계를 추정하지 않습니다. 핵폭탄은 연구 여부와 관계없이 게임 시작부터 나타납니다. 공장 아래는 에너지, 병참 상황 아래는 보급 효율, 수송 아래는 수송 효율 막대이며 0..1의 서버 값이 있을 때만 초록색으로 채웁니다. 작은 창에서 모든 지표가 들어가지 않으면 상단 줄에 마우스를 올리고 휠로 나머지 지표를 볼 수 있습니다. 모든 화면 크기에서 공용 메뉴 탭의 라벨을 숨기고 작은 원본 버튼 안에 아이콘을 중앙에 표시하며 메뉴 이름은 툴팁과 접근성 이름으로 제공합니다. 연구에서 다른 메뉴로 전환하면 연구 세션을 닫고 서버에서 해당 국가 현황을 새로 조회합니다. 패널 폭은 첨부된 2560px 화면과 TFR 원본 `interface/country*view.gui`의 컨테이너 폭을 기준으로 합니다. 국가 정보 726px(약 **28.4%**), 무역·경제 620px(약 **24.2%**), 군수 560px(약 **21.9%**), 연구·정보기관·모병·건설·생산·결정·장교단은 550px(약 **21.5%**) 비율로 표시합니다. 작은 창이나 큰 Minecraft GUI 배율에서는 글자와 버튼을 위해 국가 192, 무역 184, 기본 168 GUI 단위의 최소 폭을 보장합니다. 원본 파일은 개발 때 치수만 참조하며 실행 시 Steam 설치를 요구하지 않습니다. 상세 창과 전체 연구 트리는 별도로 열립니다. 사이드바에서 설정된 이동·점프·내려가기·달리기 키를 사용할 수 있고, 상세 창·검색·전체 트리·포커스 이탈 시 이동 입력을 해제합니다.

연구 슬롯 배치는 최대 6개까지 수용하며 실제로는 서버가 제공한 슬롯만 표시합니다. 현재 국가의 최대 슬롯 수는 5개이고 클라이언트에서 빈 슬롯을 추가하지 않습니다. 페이지 번호와 좌우 이동 버튼은 표시하지 않습니다. 슬롯 원본 이미지는 배경으로 유지하고 진행 중인 기술 이미지를 슬롯 중앙에 겹쳐 표시합니다. 슬롯에는 순번을 붙이지 않고 연구 선택 라벨을 배경 안쪽으로 내려 배치하며 저장 일수 문구는 슬롯에서 숨기되 서버의 저장 일수와 남은 연구 기간 계산은 유지합니다. 남는 세로 공간은 상단 연구 배너에 배분합니다. 내부 8개 연구 분야를 유지하며 화면에는 보병, 지상 & 항공 지원, 기갑, 포, 해군, 해군 지원 장비, 공군, 공학, 산업의 9개 아이콘 탭을 표시합니다. 탭에는 라벨을 붙이지 않고 툴팁과 접근성 이름만 제공합니다. `category/`와 `tabs/`는 같은 원작 UI 아이콘을 사용하며, 선택한 탭의 아래 테두리는 연구 패널에 이어집니다. 기술 상세에도 해당 아이콘 탭을 부착합니다. 모든 이미지는 원본 비율을 유지합니다. 상단 연구 배너만 영역을 채우도록 중앙 부분을 잘라 표시하고 나머지는 지정 영역 안에 중앙 정렬하며, 탭·사진의 최대 크기는 패널 너비와 독립적으로 제한합니다.

휠로 세로 이동, 가로 휠·우클릭 드래그로 트리를 이동합니다. 기술 상세에서 이미지·연구일·효과·해금 장비를 확인하고 실제 시작·중단을 요청합니다. TFR 전체 DLC 연구 416개를 원본 좌표와 선행 연결로 표시합니다. 보병·지원·해군·해군 지원은 가로형, 기갑·포병·공군·공학·산업은 세로형입니다. 원본 기술은 작은 카드로 표시하고 사진·이름을 유지하며 전체 이름은 툴팁에서도 확인합니다. 겹치는 원본 카드는 필요한 부분만 이동합니다. 기존 예제 기술은 진행·완료 이력이 있을 때 함께 표시합니다.

정보기관은 서버가 제공한 고용·해고, 임무 및 대상 선택, 13개 업그레이드, 해독 시작·정지·공개, 3개 작전 준비·취소를 지원합니다. 비용·조건·소유권·진행·저장은 서버에서 처리하고 클라이언트는 일회용 세션 리비전으로 요청합니다. 국가 중점 목록은 현재 이벤트 플래그·분기·선행 조건을 재조회합니다. 지휘관 상세는 실제 서버 능력치와 배속 군을 표시합니다.

게임 시작일은 **2020-01-01**이며 X1은 **10틱/시간**, 속도는 일시정지·X1~X5입니다. 보병 연도 축은 **2000년부터**, 기갑은 **1980·2018·2020·2022·2024·2028·2032년**입니다. 원본 416개 외에 기존 예제 기술 8개의 저장은 유지합니다. 국가 효과 29종(215항목)과 9개 기술의 시설 해금은 실제 서버 계산에 연결됩니다. 원본 장비·모듈·부대 해금, 장비별 능력치, 일부 경제 및 국가별 완료 스크립트는 상세창의 적용 대기 항목이며 실행하지 않습니다. 정치·경제 등 기본 메뉴는 읽기 전용 현황이며 전체 법률 교체 UI, 원작 후보 요원·무작위 작전 단계, 육해공군 잠입·거짓 정보 작전, 지휘관 특성 트리·임명, 3D 미리보기는 아직 이식되지 않았습니다. 첩보는 HOI 코어에 구현된 세 작전과 실제 기간·조건을 사용합니다. 실제 다중 접속 인증·진행·팩 다운로드 검증은 별도입니다.

## 소스와 프로토콜

| 경로 | 내용 |
|---|---|
| [client](client/src/main/java/dev/hoi/client) | 연구 UI·입력·클라이언트 네트워크 |
| [protocol](protocol/src/main/java/dev/hoi/protocol) | 공유 연구 패킷·읽기 전용 화면 데이터 |
| [클라이언트 테스트](client/src/gametest) | 실제 Minecraft 렌더러 테스트 |

기존 [HOI의 `2567c2f`](https://github.com/Kyarurung/HOI/commit/2567c2fb7b439835e64d1220690be22dbc30792d)에서 분리했습니다. 원래 개발 이력은 HOI에 남아 있습니다. `protocol/`은 [HOI의 같은 모듈](https://github.com/Kyarurung/HOI/tree/main/protocol)과 동일한 소스로 시작합니다. 공유 모듈을 수정할 때는 두 저장소에 함께 반영하고 호환되지 않는 변경은 패킷 버전도 올립니다. 자동으로 다른 저장소의 소스를 가져오지는 않습니다.

수신기 등록 전 `ResearchProtocol.registerPayloadTypes()`를 호출해야 합니다. 독립 모드 초기화 순서에 의존하면 서버 시작이 실패합니다. 게임 수치·비용·완료 여부는 서버만 결정합니다.

## 서버 명령과 시간 표시

클라이언트는 /hoi 루트를 등록하지 않습니다. 이전 버전의 client-sided command 오류는 클라이언트 루트가 서버의 start·map·ready·stop을 가로챈 것이 원인입니다. 최신 클라이언트 JAR로 교체하고 클라이언트를 재실행하세요. /hoi research는 서버가 화면 열기를 요청하고 클라이언트가 기존 인증·요청 제한을 적용하는 OPEN 요청을 보냅니다. R과 /hoi-research는 독립적인 단축 입력입니다.

날짜·시간은 2020년 1월 1일 01시, 배속은 1배속~5배속으로 표시합니다. 배속 색상은 초록·노랑·주황·빨강·진한 빨강이며 | 구분선은 진한 회색입니다. 배속과 일시정지는 관리자만 변경합니다. 관리자 /hoi stop은 국가 선택과 캠페인을 초기화하고 2020년 1월 1일 00시·일시정지로 되돌립니다. 초기화 백업은 서버에서 보관하며 Minecraft 서버 자체는 종료하지 않습니다.

클라이언트 GameTest는 실제 등록 함수를 호출하여 /hoi를 등록하지 않고 /hoi-research만 등록하는지 확인하며, 연구 헤더의 한국어 날짜·배속을 실제 렌더러로 검사합니다. 운영 서버와 플레이어 클라이언트의 재접속 검증은 별도입니다.

UI를 열어 수치·기술·무기를 생성하지 않습니다. UI GameTest의 채워진 막대와 수치는 화면 검증용이며 실제 다중 접속의 동기화를 증명하지 않습니다. 새 HUD 아이콘 팩과 HOI 서버 개발 빌드가 함께 필요하며 운영 서버는 자동으로 시작하거나 재시작하지 않습니다.


## TFR 연구·혜택 검증 (2026-09-08)

배너 아래에 제한된 혜택의 남은 횟수와 국가 연구 속도를 표시합니다. 혜택 버튼은 종류·대상·속도·선행 연도 감소를 안내합니다. 선택한 슬롯이 사용 중이면 남은 빈 슬롯을 자동 선택하고 서버도 이를 검증합니다. 선행 AND/OR, 배타 분기, 국가별 중점·플래그 조건과 예상 일수를 서버가 결정합니다. 슬롯을 중단·재개해도 혜택을 다시 소비하지 않습니다.

연구 payload는 v2이며 서버와 클라이언트의 공유 protocol 소스를 함께 갱신해야 합니다. v1 연구 패킷과 호환되지 않습니다. 상한은 512개 기술, 16개 슬롯, JSON 400,000문자입니다. 국가 메뉴·첩보 payload ID는 유지됩니다. 원본 사진 412개는 HOI-resourcepack에서 읽고 누락된 4개는 기존 분야 아이콘으로 표시합니다.

`test runGameTest remapJar`는 416개 시험 스냅샷으로 모든 탭의 배치·클릭, 가로·세로 방향, 슬롯 자동 선택, 혜택·상세창과 작은 창을 확인합니다. 실제 Minecraft 렌더러의 `hoi-tfr-*` 스크린샷을 `client/build/run/clientGameTest/screenshots/`에 기록합니다. 시험 값 +4%·혜택 2회는 국가에 지급하지 않습니다. 전체 fixture는 배포 JAR에 포함하지 않습니다. 실제 운영 서버 연결에서 연구 시작~완료, 지연·재접속, 리소스팩 다운로드 검증은 남아 있습니다. 운영 서버를 자동 변경하거나 시작하지 않습니다.

기갑 33개와 산업 60개는 2026-09-08 추가 스크린샷에 맞춘 전용 배치입니다. 기갑은 엔진·정찰전차·주력전차·수륙양용·장갑·보조 무기/탄약의 열을 분리하고, 차체만 넓은 카드로 표시합니다. 산업은 작은 정사각형 아이콘으로 생산·산업·건설/채굴·합성 석유를 구분합니다. 같은 행의 연구는 좌우로 연결하며 다른 행은 공통 분기선으로 연결합니다. 기존 원본 좌표에 겹침이 있어도 해당 열을 유지합니다. 양쪽 연도 축은 화면 참조이고 실제 기술 연도·효과·선행 조건은 서버 정보를 그대로 사용합니다. 큰 화면에서는 비율에 맞춰 확대하고 작은 화면은 스크롤로 접근합니다. 416개 기술 전체에 9개 탭별 고정 배치를 적용합니다. 연구 탭은 좌측에 나란히 놓고 본문 상단에 붙이며 원본 선택·비선택 프레임을 전환합니다. 기술 갈래는 원본 XOR 이미지로, 특별 묶음은 테두리로 표시합니다. 기술 검색과 처음 위치/슬롯 목록 버튼은 없으며 Esc로 돌아갑니다. `hoi-armor-rearranged`, `hoi-industry-rearranged`와 소형 창 스크린샷으로 검증합니다.


## 건설 예약과 공장 배정

건설 메뉴는 원본 비율의 왼쪽 패널과 원본 건물 아이콘을 사용합니다. 건물을 선택한 뒤 1인칭 시점에서 지도 위의 자국 주를 클릭하면 서버가 소유권·현재 통제·연구·슬롯을 검사하고 건설을 예약합니다. UI를 닫은 건설 지도에서도 선택한 건물로 주를 클릭할 수 있습니다. 목록의 우선순위 변경·취소와 수리 우선 공장 −/+는 서버에 요청하고 저장합니다. 수리 우선 공장은 제목과 분리된 숫자 칸을 사용합니다. 작은 창의 건설 목록과 건물 아이콘 목록은 각각 스크롤합니다.

소비재·무역/기관 예약을 먼저 제외하고, 손상 건물이 있을 때 수리 우선 공장을 확보한 뒤 각 건설에 최대 15개를 배정합니다. 남는 공장 중 최대 15개는 수리에 사용하며 나머지는 미사용으로 표시합니다. 같은 날 건설을 마친 공장을 수리에 중복 배정하지 않습니다. 소비재, 사용/총 공장, 미사용 공장, 건설 속도, 에너지 공급/수요 및 실제 수리 배정은 같은 서버 계산을 사용합니다. 에너지 충족률은 상단 공장 아래 막대에도 반영합니다. 수리 설정은 기존 국가 저장에 선택적으로 추가되어 이전 저장은 0개 우선 지정으로 시작하며 진행을 초기화하지 않습니다.

현재 건설 가능한 종류는 등록된 민간공장·군수공장·조선소·기반시설·공군기지·대공포·레이더·정제시설·연료 저장고 9종입니다. 조선소는 항구가 있는 주에만 예약합니다. 나머지 원본 아이콘은 조건 안내와 함께 비활성화하며, 미등록 발전소·댐·원자로·지역 시설을 임의 생성하지 않습니다. 에너지는 현재 등록된 석탄 자원과 무역 결과를 이용합니다. 공급은 `10 + 9 × 석탄`, 수요는 `공장 수 × min(6.6, 0.25 + 0.0125 × 공장 수)`인 현재 HOI 규칙입니다. 에너지 충족률에 따라 건설 공장당 작업량은 4~5, 군수공장 생산은 3.5~4.5, 조선소 생산은 2~2.5로 변합니다. 발전소 생산·특수 프로젝트 수요·TFR의 모든 에너지 보정과 전력 거래는 아직 구현하지 않았으며 원작 전체 전력망과 동일한 계산으로 간주하지 않습니다.

건설 요청/응답은 공유 `hoi:construction_request_v1`·`hoi:construction_response_v1`을 사용합니다. 서버가 발급한 세션과 단일 사용 리비전으로 중복 예약을 차단하고, 국가 권한 상실 시 화면을 닫습니다. 지도 요청에는 국가나 주 ID 대신 제한된 시선 방향을 보내고 서버가 플레이어 위치에서 주를 찾습니다. 기존 연구 payload는 변경하지 않습니다.

검증에는 공장 배정·에너지 부족·저장 복구 JUnit, 실제 지도 좌표와 일반 지도 클릭의 서버 GameTest, 작은 창의 수리 버튼·목록 스크롤·권한 만료를 포함한 실제 클라이언트 렌더링이 포함됩니다. UI fixture와 mock 서버 플레이어 검증이며 실제 다중 접속의 클라이언트→서버 왕복·재접속·팩 다운로드 검증은 별도입니다. 운영 서버는 시작하거나 재시작하지 않습니다.
